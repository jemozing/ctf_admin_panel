# Сообщения об уязвимостях

Для непубличного сообщения используйте GitHub → Security → Advisories → Report a vulnerability, если владелец репозитория включил private vulnerability reporting. Если этот канал недоступен, создайте issue только с просьбой предоставить приватный контакт, без технических подробностей и секретов.

Укажите затронутую версию/commit, необходимые права, воспроизводимые шаги на синтетическом сервисе, ожидаемое и фактическое поведение. Не прикладывайте рабочие токены, пароли, игровые флаги, дампы БД, PCAP или снимки панели с реальными данными.

Проект находится в разработке; поддерживается текущая версия основной ветки. Полная эксплуатационная приёмка на целевом Linux-хосте остаётся открытой: [состояние проверок](docs/progress.md).

Executor имеет доступ к Docker и управляемым каталогам хоста. Разворачивайте панель на выделенном CTF-хосте, ограничивайте доступ к ней и следуйте [модели угроз](docs/threat-model.md) и [инструкции развёртывания](docs/container-deployment.md).
