# Модель угроз MVP

Дата фиксации: 19 октября 2026 года. Область: один Linux vulnbox одной доверенной команды. Документ задаёт требования реализации; таблица не утверждает, что все меры уже реализованы на этапе 0.

## Активы и границы доверия

Приоритетные активы — игровые флаги и состояние БД, идентичность volumes/сетей/портов, сохранённые рабочие образы, manifests и secret versions, доверенная политика executor, критический журнал операций и доступность работающих контейнеров.

Недоверенные источники: игровой HTTP/TCP-трафик, содержимое уязвимых контейнеров, source workspace, активные каталоги после компрометации приложения, Compose/Dockerfile, имена файлов, symlinks, логи, diff, строки ошибок Docker, любые HTTP/WebSocket и IPC payloads. Участник с ролью Defender имеет право исправлять приложение, но это не даёт права расширять host privileges через Compose.

Web работает отдельным UID без Docker socket, записи в executor DB, snapshots, staging и secrets. Executor имеет повышенные полномочия; его протокол предоставляет ограниченные типизированные действия, а не shell или Compose-аргументы. Web Admin готовит и подтверждает регистрацию по immutable proposal ID и digest через панель. Executor проверяет указанный путь по локально заданным корням, поддерживаемому профилю и фактическому runtime; подтверждённый объект нельзя подменить. Обязательного локального CLI-подтверждения каждого сервиса больше нет. Компрометация dashboard даёт возможность отправлять допустимые регистрации внутри заранее подключённых корней; она не должна позволять расширить эти корни или профиль привилегий. Роли пользователей проверяются dashboard, а peer UID и границы файловой/Docker-политики — executor.

Git-процесс получает только HTTPS URL/ref, временный каталог и ограниченный read-only credential. Он запускается без root и дополнительных групп, без доступа к Docker/IPC/vault; конфигурация из игровых `.git` и пользовательского окружения не наследуется. Hooks, filters, submodules и transport helpers запрещены. Полученное дерево считается недоверенным; только проверенные управляемые пути публикуются как immutable кандидат. Настройка Git доступна Admin, выполнение заранее настроенного fetch — Admin/Defender. Полная изоляция сети и Git-парсера не заменяет обновление Git и лимиты ресурсов.

| Угроза | Требуемая мера | Проверка |
|---|---|---|
| Компрометация приложения пытается записать секреты или политику executor | Разные UID, защищённые корни вне mounts/active/source, Unix socket с правами, проверка peer credentials | A20, A21 |
| Compose-патч добавляет privileged, host namespaces, devices или host mount | Нормализация и сравнение с утверждённой политикой до build/deploy; отдельное локальное утверждение расширения | A21 |

| Под видом кода в snapshot попали флаги, БД или mount | Явная непересекающаяся карта файлов/данных, исключение nested mounts, подтверждение администратора | A02, A03, A10 |

| Двойной клик, потеря HTTP-ответа или параллельные Web/CLI | Долговечная идемпотентность, единая очередь, locks реальных конфликтующих ресурсов | A11–A13 |
| Процесс падает после фактического действия до записи результата | Write-ahead intent, обнаружение принадлежащих операции объектов, сверка, защищённый recovery point, `requires_recovery` вместо ложного success | A14–A16 |

| Бесконтрольные логи, сборки и staging заполнили диск/память | Квоты, bytes/inode preflight, ограниченные потоки и очереди, приоритет аварийного возврата | A16, A23, A27 |
| CSRF, украденная или заблокированная сессия, WebSocket обход RBAC | Серверные сессии, HttpOnly cookies, CSRF, Host/Origin, RBAC каждого action/stream, отзыв доступа открытых потоков | A20, A24 |
| Экспорт раскрывает environment, секреты или действующие сессии | Редактирование секретов во всех конфигурациях, ссылки вместо значений, ограниченные права, аннулирование сессий при восстановлении | A26, A28 |

## Решения и ограничения

Docker socket предоставляет полномочия, близкие к root на хосте; безопасность не обеспечивается одним запретом `privileged`. Набор mounts, namespaces, devices, capabilities, сетей и build contexts подтверждается как политика. Сборка недоверенного Dockerfile запускается через зарегистрированный профиль и имеет отдельные ограничения. На первом этапе изменяющие web endpoints не включаются до готовности авторизации.

Команда отвечает за полноту карты значимых данных и допустимость автоматических миграций самого приложения. Обнаружение mounts не доказывает отсутствие данных в writable layer. Простой snapshot кода не восстанавливает схему БД. Безопасность игрового сервиса после применения патча и корректность checker организаторов не гарантируются панелью.

Полная компрометация root, Docker daemon, ядра или executor находится за пределами защиты. Локальные snapshots и manifests не защищают от потери диска. Злонамеренный администратор хоста может отменить эти ограничения. Сетевая интеграция checker и произвольные декодеры трафика относятся к последующим выпускам с отдельной моделью угроз.

## Запланированное расширение: HTTP Proxy / WAF

Дополнение от 20 октября 2026 года, ТЗ v2.5. **Не реализовано и не включено в текущую приёмку MVP.** Подробные требования и P01–P16 находятся в [плане proxy](http-proxy-waf-plan.md).

При opt-in подключении proxy становится частью пути игровых запросов. Его доступность проверяется отдельно от dashboard/executor; отказ самого proxy не компенсируется обещанием автоматического обхода. Последняя рабочая конфигурация, аварийный CLI и подтверждённый возврат прямых портов обязательны.

| Угроза нового модуля | Требование плана |
|---|---|
| Атакующий HTTP payload компрометирует proxy/recorder и получает полномочия executor | Отдельные непривилегированные компоненты без Docker socket, executor IPC/vault/служебных БД и игровых файловых mounts; ограниченные private management/ingest API |
| Произвольный Host/upstream превращает proxy в открытый relay/SSRF | Только утверждённые service routes и сети; upstream не берётся из клиентского запроса; bind/route loops проверяются |
| Несогласованные HTTP framing/normalization меняют запросы или checker | Один проверенный engine, объявленный профиль HTTP, отказ неоднозначного framing, прикладные compatibility tests и реальные checker-прогоны до cutover |
| Поддельный X-Forwarded-For обходит WAF, NAT банит всю команду/checker | Peer IP по умолчанию, явная trusted chain, нормализация IPv4/IPv6, per-service scope, observe-only, проверенные исключения и ограниченный TTL |
| Журнал содержит credentials, игровые флаги или исполняемый HTML | Redaction до хранения/выдачи, отдельный sensitive_access, безопасный text/hex viewer, bounded decoding и аудит чтения без payload |
| Flood/churn IP/большие тела/compression bomb исчерпывают ресурсы | Bounded buckets/bans/queues/body capture/decompression, quotas/rotation, проверенный WAF fallback и счётчики потерь |
| Отказ записи трафика или медленный браузер останавливает игру | Неблокирующий recorder и независимый forwarding; degraded/dropped видны, а не выдаются за отсутствие трафика |
| Перенос портов ломает runtime policy или уничтожает данные | Отдельный Admin preview/digest, сохранённые bindings/сети, новая доверенная ревизия, проверенный cutover/rollback без отката игровых данных |
| Ошибка политики/рестарт открывают сервис без объявленной защиты | Validate-before-activate, last-known-good, desired/applied revision, сохраняемые сроки bans, выбранная политика деградации и локальное восстановление |
