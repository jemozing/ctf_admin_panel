## Окна операций при HTTP-доступе по сетевому адресу — 2 ноября

Исправлен синхронный сбой `crypto.randomUUID is not a function`, который очищал интерфейс при открытии «Подготовить»/«Применить» через HTTP по IP или сетевому имени. Ключ операции создаётся один раз на окно из 16 случайных байт `crypto.getRandomValues()` и сохраняется между Preview, локальными подтверждениями и Submit.

В Chromium на настоящем insecure HTTP origin исходная сборка воспроизвела TypeError до запроса Preview, исправленная прошла 9 browser checks. Проверены оба окна, смена релиза, стабильность ключа, `plan_digest`/CSRF, отдельное подтверждение и видимая ошибка Preview. Использован собранный frontend с синтетическим API на loopback; это дополнение к A19, без реального Deploy/Rollback. Production frontend build, 43 helper-теста и 157 packaging tests пройдены. Go-код не менялся; VM/Docker и игровые сервисы не использовались, статусы Linux/CTF-приёмки не повышаются.

## Разработка трафика завершена в заявленных профилях — 30 октября

Реализованы оставшиеся функции этапов 10.2–10.4: двунаправленные TCP-потоки, UDP-датаграммы, HPACK/HTTP2/gRPC, gzip, protobuf descriptors через Admin preview/digest/confirm и отдельная HTTPS/2 → h2c termination. Capture расширен на несколько Docker bridge-сетей компонента, bridge-member veth и host-publication альтернативы с canonical leg и защитой management ports. Исходные observations сохраняются, TCP byte ranges объединяются без удаления настоящих повторов. Source/release pins, missing/mixed versions, file drift и descriptor blob integrity не позволяют подставить случайную схему к историческим bytes.

Вкладка «TCP-потоки / gRPC» связана с реальным private archive/API. Список metadata-only, payload/decoder/descriptors требуют sensitive доступа, schema mutation — Admin. Во время RPC права проверяются повторно; при отзыве сессии или сбое аудита bytes удерживаются. Parser/reassembly работают в capability-free archive с ограничениями памяти/времени. TLS keylogs, произвольный L4 forwarding, HTTP3/QUIC и автоматическая Any/reflection не включены.

Финальный полный `make test-race vet frontend-check packaging-check build proxy-build capture-build` — PASS за 212.911 с; helpers H2/analysis дополнительно проходят vet. Проверки реальных отдельных процессов охватывают прежние HTTP1/TLS и новые H2/gRPC/flows/schema, затем реальную навигацию в headless Chromium на приватном локальном стенде: 39 API/hook проверок и 14 browser checks, без подмены analysis API. Проверены выбранный descriptor и именованный JSON; загрузка schema отдельно подтверждена API-тестами, browser upload не заявляется. Подробные counts/digests, ограничения и cleanup: [traffic-development-2026-10-30.json](../tests/integration/reports/README.md#report-traffic-development-2026-10-30-json). [Контракт и использование](traffic-analysis.md), [матрица C01–C10](packet-capture-plan.md).

Разработка текущего traffic-выпуска завершена, Linux/Compose/CTF приёмка 10.5 открыта. VM/SSH/Docker runtime не использовались. Live AF_PACKET, реальные NAT/bridge/checker, CPU/RAM/drop rate и общая вместимость 4 GiB не объявляются проверенными. A01–A39 и P01–P16 не закрываются этими результатами. ## Пассивный захват TCP/UDP и PCAP — 30 октября

Реализованы отдельные `ctfm-capture` / `ctfm-packets`, opt-in Compose и вкладка «Трафик → Пакеты». Есть фильтры, live/pause/cursor pages, безопасные hex/ASCII, ограниченный PCAP. Admin выбирает только runtime-derived targets и подтверждает preview/digest; raw/export требуют sensitive access, свежей сессии и аудита. По умолчанию сохраняются метаданные, bytes включаются явно. Перед изменением runtime/компенсацией захват приостанавливается; короткий lease не позволяет забытым scope работать неограниченно.

Первый профиль — одна подтверждённая private Docker bridge-сеть на application-компонент с точными interface name/index. Полная NAT/host/veth-карта, глобальная дедупликация межсетевых flows, TCP streams, gRPC decoder, TLS decryption и L4 enforcement не приняты. Новый модуль не меняет маршрутизацию или игровые данные.

## Групповой перенос компонентов и портов — 30 октября

Расширен Admin flow: один план содержит все публикуемые application-компоненты и контейнерные TCP-порты сервиса. Пределы — 8 компонентов, 16 target-пар и 32 явных listeners; для каждой пары выделяется уникальный разрешённый private backend-порт. В интерфейсе есть обязательная таблица портов, HTTP/TLS/capture для каждого target, точный Host каждого listener и общая service-scoped WAF политика. Неполное покрытие и повторные backend-порты блокируются.

Worker переключает компоненты последовательно, одним пересозданием меняя весь набор портов компонента. Durable intent, наблюдаемые ID и mixed overlay фиксируются по шагам. Групповой возврат и компенсация сохраняют текущие образы, смонтированные данные и ID незатронутых зависимостей; исходный Compose не редактируется. Recovery отдельно проверяет original/private состояние каждого компонента и опору для каждого отсутствующего приложения. Legacy однокомпонентные proposals/overlays/history поддерживаются без переписывания старых digest.

Финальный общий `make test-race vet frontend-check packaging-check build proxy-build` — PASS за 153.189 с. Пройдены 31 cutover test functions (17 прежних и 14 новых), 23 frontend helpers и 143 packaging tests. Отдельно пройдены 10 HTTP и 15 TLS regression-проверок на финальных бинарниках; все три бинарника собраны для Linux/amd64 без запуска. Исправлены API-имена компонентов, ID записи overlay для web-generated service ID, ложный конфликт health перехода и невозможные wildcard listeners. Процессы и временные fixtures очищены.

## Перенос портов и TLS — первый профиль, 30 октября

Добавлен отдельный Admin flow «перенести занятый порт» с точным preview/digest, durable очередью/этапами и подтверждённым возвратом. Все исходные публикации одного application-компонента заменяются одним закрытым loopback backend; proxy получает прежние внешние адреса. Версионируемый overlay не редактирует исходный Compose и применяется при последующих Deploy/Rollback/Recover. Возврат сохраняет текущий релиз и смонтированные данные. Неизвестные образы, runtime settings, mounts или внешняя политика останавливают автоматическую компенсацию; новый план восстановления показывает фактические контейнеры и отдельно сохранённую опору. Единственный worker выполняет startup reconciliation, CLI admission согласован между процессами.

TLS termination добавлена в engine и панель: выбор immutable-профиля, точный Host, SAN/SNI, сроки/цепочка, TLS 1.2+ и ALPN HTTP/1.1. Ключи находятся только в отдельном read-only mount proxy. Импорт — `scripts/proxy-tls-import.py`, ротация — новым ID. Ошибочная политика сохраняет LKG, pins переживают restart. Добавлен CLI возврата через живой executor без зависимости от dashboard.

Финальный общий прогон `make test-race vet frontend-check packaging-check build proxy-build` — PASS за 138.909 с. Пройдены 19 frontend helper tests и 143 Python packaging tests; все три бинарника собраны для Linux/amd64 без запуска. ## Полный журнал VirtualBox — 29 октября

Конфигурация остаётся 4 vCPU / 4 GiB, CPU execution cap 100%, balloon 0. В начале сессии на Windows было свободно 36,2 GiB из 47 GiB; позднее давление на ресурсы одним startup-снимком не исключается. ## Приёмка 20 октября

Исправлен дефект долговечности SQLite: `storage.Measure` открывал/закрывал обычные файловые дескрипторы для активных DB/SHM в процессе writer, тем самым снимая POSIX record locks. Другой CLI/SQLite процесс после этого мог удалить живые WAL/SHM; writer продолжал видеть данные через уже удалённые inode. Теперь Linux измеряет метаданные через `O_PATH|O_NOFOLLOW`, Darwin — через `Root.Lstat`. Проверки inode, прав, hard links, symlink и mount ID сохранены. Межпроцессный regression воспроизводит отказ на старой реализации и проходит на новой; после quota scans оба процесса видят commits, sidecar identities сохраняются, повторное открытие БД читает все записи.

Это подтверждённая ошибка приложения, а не несовместимость Python reader или только старого образа. Ранние отрицательные/forensic отчёты сохранены; они не объявляются успешной долговечной приёмкой. Новый production workflow на `c2f131aae98e…` проверил linked WAL до/после каждого CLI, равенство live Python/offline SQLite, пять switch observations, отсутствие terminal locks и последующее успешное задание.

Исправлено ограничение строк логов: очистка управляющих символов выполняется до усечения до 16 KiB; граница усечения сохраняет корректный UTF-8. Секреты маскируются до обеих операций. Проверены длинные строки, 100 000 переводов строки в одном frame, повреждённый mux header, фильтры и медленный WebSocket-клиент. Новые HTTP/WS/Unix-RPC тесты проверяют запрет всех изменяющих действий Viewer, серверную идентичность Defender и отзыв четырёх видов доступа при незавершённом чтении приватного кадра.

Новый реальный Docker fault-прогон проверяет EROFS при Apply, неуспешный Recover, частичное переключение двух приложений и новый явно подтверждённый Recover. Обе SQLite-БД, mounts и identities зависимостей сохранены; detail API показывает разные фактические версии компонентов. Отдельные Linux проверки вызывают настоящий EFBIG посреди Apply и настоящий ENOSPC для SQLite WAL: частичный результат не выдаётся за успех, исходные mutation intent/recovery point/locks сохраняются.

Окончательные локальные образы: executor `c2f131aae98e…`, dashboard `1d0cf9d4439a…`; SHA-256 общего бинарника `225f577c2b10ac2045f054f78c8cba8f2d171a6334280ae5c34eb7003cb5ce3b`. Полный `make test-race vet fixtures-check`, frontend build, 7 Node и 10 packaging tests прошли. Повторный Compose smoke этих образов прошёл. Существующие preview/SibirCTF были остановлены до начала работы и не запускались; новые испытания используют только собственные временные проекты.

После окончания приёмочных прогонов только два остановленных контейнера существующей панели пересозданы с исправленными образами через Compose `create`, без запуска. 12 зарегистрированных игровых контейнеров сохранили ID/image/running/StartedAt. Остановленная preview БД проверена через отдельную копию: целостна, содержит 6 сервисов и 0 locks; её исходные файлы не менялись.

Целевой Linux/amd64, restart отдельного daemon, недоступный registry для самого daemon и ошибки fsync/power loss остаются открытыми. Это выходные проверки этапа 7; статус этапа 9 не повышается до реализации.

## Исторические проверки упаковки (19 октября)

Упаковка также проверена командами `docker compose config --quiet`, `docker compose build`, `make packaging-check`: восемь проверок bootstrap/path policy, optional readonly Docker data root и слияния Compose. Root bootstrap дважды запущен в одноразовом Linux-контейнере: проверены владельцы, modes и идемпотентность. На macOS shared bind не сохранил требуемый GID: bootstrap отклонил его; для интеграционного smoke использовано native Linux storage. Это ограничение среды не обходится ослаблением production-разрешений.

Выполнены общий Go race-прогон и `go vet`; frontend прошёл TypeScript/Vite сборку и пять тестов границ графиков. Упаковка прошла девять проверок, включая пять отдельных RO host procfs sources только у executor. В UI дополнительно проверена страница host-метрик с живыми CPU/RAM/load/uptime, графиками и filesystem/inode показателями на стенде с пятью подключёнными сервисами. Ранее отдельно проверены login, недоступность executor, список команды и диалог.

Native `init-admin` имеет отдельные тесты: отсутствие зависимости от executor bootstrap, ограниченный stdin, приватный password file, первый Admin без вывода пароля и отказ повторного bootstrap. Go-тесты транспорта требуют разрешения на Unix socket; отказ sandbox в bind не считается дефектом приложения или успешной проверкой. Итоговые прогоны необходимо выполнять вне этого ограничения или в Linux-контейнере.

## Ограничения и ближайший выходной критерий

ТЗ v2.4 возвращает в обязательный MVP веб-регистрацию по пути с подтверждением Admin через панель без CLI и HTTPS Git URL для GitHub/GitLab. Реализация выполнена в существующих executor/dashboard и общем pipeline кандидатов; сквозной HTTP smoke сохранён для итоговых образов. Критерии A37–A39 разделяют этот результат и оставшиеся испытания. Остальные обязательные функции приложения, перечисленные выше, реализованы; следующим этапом остаётся их сквозная приёмка. SSH, API провайдеров, polling и webhooks остаются после MVP.

Named-volume и production-container bind циклы завершены: baseline → Prepare → Build → Deploy → Rollback, сохранены флаг/state и ID незатронутой БД. Шесть SIGKILL границ дополнены partial multi-component switch, EROFS Apply/Recover, kernel EFBIG посреди Apply и SQLite ENOSPC с сохранением mutation intent/locks. Финальная пятиминутная нагрузка и down/up собственной панели при непрерывной записи пяти игр прошли. 29 октября получены native Linux/amd64 Compose и 13 workflow checks; для остальных сценариев требуется стабильная VM без RCU/soft-lockup. Открыты недоступность registry самому daemon, контролируемая аварийная приёмка restart daemon, fsync EIO/power loss, полная браузерная/Docker-driver pressure серия и цели competition-4g. Адреса HTTP-проверок должны быть доступны из bridge-сети executor: host-loopback URL native smoke в контейнере не эквивалентен. Эти испытания не заменяются эмуляцией amd64 или unit tests.

Файловый профиль пока отклоняет symlinks и переходы file↔directory; неподдерживаемые layouts хранения и runtime-настройки блокируются. Все пять SibirCTF прошли реальные браузерные циклы на явно подготовленных профилях. Постоянные данные вынесены из обновляемого кода; зависимые PostgreSQL/MinIO не пересоздаются, RAM neurolink сохраняется только при неизменном auxiliary. Исходные неподходящие upstream layouts не считаются безопасными автоматически. Пробы выполняют обычные операции приложения независимо от панели; встроенные URL checks в этих пяти профилях не настроены, checker организаторов неизвестен. Все реальные прогоны используют локально помеченный baseline и один pinned upstream commit. Окончательный выпуск MVP возможен только после устранения оставшихся обязательных пробелов матрицы и проверки целевой среды.
