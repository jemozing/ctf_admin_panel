# Поддерживаемый профиль Docker Compose

Профиль `mvp-v1`, контракт этапа 0. Целевой runtime — Linux/amd64, локальный Docker Engine и установленный Compose v2 plugin. Конкретные проверенные версии фиксируются в отчёте Linux-стенда. Локальная сборка на macOS или разбор YAML не доказывают совместимость с Linux и не заменяют испытание Docker.

## Поддерживаемые возможности

| Особенность | Условия |
|---|---|
| Несколько компонентов app/db/cache | Один контейнер на Compose component в начальном профиле, роли подтверждены |
| Несколько Compose-файлов | Порядок `-f`, project directory и точное исходное project name зафиксированы |
| Profiles | Набор выбранных profiles фиксирован; неизвестные компоненты не включаются автоматически |
| Лимиты локального Docker Compose | `deploy.resources.limits` с CPU и памятью при импорте приводятся к эквивалентным `cpus` и `mem_limit`. Конфликтующие значения отклоняются. |
| Env files и secrets | Значения импортированы в immutable versions executor; в Release и web только refs |
| Локальный Dockerfile/context | Все пути внутри утверждённых roots; staging вне active/source/data mounts |
| Готовый image | Полный локальный image ID и отдельный удерживающий тег на релиз |
| Named volumes | Фактические имена существующих volumes сохранены, содержимое не копируется и не откатывается |
| Bind-mounted код/config | Явная карта путей и стабильные host sources; переключение с пересозданием выбранных контейнеров |
| Bind-mounted данные | Отдельные непересекающиеся пути, прежняя точка привязки сохраняется |
| Существующая external network | Используется подтверждённая идентичность без автоматического создания замены |
| Временные данные в writable layer/tmpfs | Потеря явно подтверждена администратором; они не объявляются сохранёнными |
| HTTP/TCP healthchecks панели | Только утверждённые адреса и bounded typed steps, без shell на хосте |

Начальное ограничение на один контейнер в component исключает неоднозначные replicas и горизонтальное масштабирование. Прочие поля Compose не считаются безопасными лишь потому, что их принимает `compose config`: нормализованный план должен пройти проверку политики и сверку с Docker inspect.

## Причины отказа

- Anonymous volumes в начальном профиле; значимые данные в tmpfs или writable layer до их отдельной миграции.
- Неклассифицированный mount, volume из нового `Dockerfile VOLUME`, противоречие кода и data paths.
- Privileged mode, host PID/IPC/network/user namespaces, devices, нестандартные mount drivers.
- Неутверждённые capabilities, пути bind, build contexts, порты, сети или иное расширение политики запуска.
- Lifecycle hooks, remote build contexts, динамические include/extends; требуется предварительно подготовленная простая конфигурация.
- Source workspace/staging в активном дереве или игровых mounts, подменяемый source bind/предок.
- Неустранённый drift между сохранённой конфигурацией, Docker inspect и активными файлами.
- Обязательные file attributes, которые текущая реализация не может сохранить; special files, setuid/setgid/capabilities.
- Конфликтующая независимая регистрация того же Compose project или пересекающихся managed trees.

Отказ должен назвать конкретную возможность и путь/компонент без утечки чувствительных значений. Неподдерживаемые поля не удаляются молча.

## Семантика действий

Start/Stop/Restart работают с подтверждёнными существующими container ID. Исчезнувший контейнер не создаётся заново из изменившегося Compose файла по команде Start.

Prepare и Build используют зафиксированный staging и не меняют active tree даже при code bind mounts. Compose project identity, environment inputs, конфигурация и набор целей определяются доверенной политикой. Повседневный Deploy/Rollback читает сохранённую конфигурацию executor, использует локальные точные образы и не интерпретирует заново игровые `.env` или Compose-файлы.

**«Сменить Compose»** позволяет подготовить релиз с новыми лимитами или изменить IP и фиксированный порт хоста у существующей публикации TCP или UDP. Это действует для зарегистрированных целей обновления с теми же портами контейнера и протоколами. [Порядок применения и отката](release-pipeline.md#смена-compose-через-панель).

Переключение явно ограничено подтверждёнными targets; зависимости не пересоздаются неявно. Перед заменой active code сохраняется recovery point. Named volumes и data bind mounts остаются прежними. Старый inode bind-mounted файла не считается заменённым от одного rename на хосте: проверяется пересоздание нужного контейнера и фактическое содержимое.

Автоматические `down -v`, удаление/обновление anonymous volumes, удаление неизвестных orphan containers и глобальный Docker prune запрещены. Отказ, обновление или перезапуск панели не управляет жизненным циклом игровых сервисов.

Стенд должен самостоятельно записывать/читать тестовый флаг и состояние без панели. Инструкции запуска и фактические результаты находятся в `docs/testing.md`. Реальные CTF-проекты из дополнительного набора анализируются отдельно; наличие их исходников в стенде не означает автоматическую пригодность для управляемого обновления.

## Что предстоит подтвердить интеграционно

Этап 0 фиксирует профиль и fixtures. Этапы 1–4 должны доказать нормализацию, сопоставление inspect, сохранение project identity/данных, отсутствие действий над зависимостями и offline rollback. Этап 7 фиксирует версии Engine/Compose и результаты A01–A32. До этих испытаний нельзя заявлять подтверждённую совместимость runtime.


## Граница текущего импортера

На текущем этапе рабочая вертикаль подтверждена для environment, сохранённого в executor vault. File-backed Compose `secrets`/`configs` пока не входят в принимаемый runtime-профиль: их исходные bind mounts и материализованные пути требуют отдельной сверки и испытаний. Регистрация таких проектов отклоняется; наличие низкоуровневого vault/materializer не означает поддержку их импорта. Для named volumes принимается обычный локальный driver без driver options и cluster-backed хранения; volume с options, скрывающими host bind, блокируется. Compose renderer escaping `$$` снимается ровно один раз при нормализации, затем literal `$` защищается перед повторным чтением executor-generated Compose.
