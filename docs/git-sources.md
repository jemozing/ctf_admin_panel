# Git-источники MVP

Веб-регистрация подключает существующий Compose-проект. Git URL задаёт источник последующих исправлений этого проекта; клонирование нового репозитория с автоматическим запуском его Compose не выполняется.

Войдите как Admin, откройте вкладку «Git» сервиса и укажите HTTPS URL, ref (`HEAD`, ветка, тег или точный commit) и необязательный подкаталог. Путь внутри выбранного подкаталога должен соответствовать зарегистрированным управляемым путям сервиса. Например, для проекта с управляемым `src/` и репозитория, содержащего `vuln-service/src/`, укажите подкаталог `vuln-service`.

Закрытый репозиторий требует токена с правом чтения и при необходимости имени пользователя. Токен вводится отдельно, не внутри URL. Сохранённое значение не возвращается API. Пустое поле сохраняет credential только при прежних URL и имени пользователя; замена этих полей требует нового токена либо явного удаления credentials. Секрет хранится в vault, не в `.git/config`, снимке или аргументах процесса.

Перед сохранением нажмите **«Проверить подключение»**. Кнопка есть и в пункте подключения Git мастера регистрации. Проверяется доступ к самому HTTPS Git-репозиторию с указанными данными; при успехе появятся основная ветка и список **«Выбрать ветку»**. Выбор подставляет полный ref, например `refs/heads/main`. Повторная проверка подтверждает выбранную версию и показывает Git SHA, объявленный сервером. Ветку, тег или SHA можно по-прежнему ввести вручную.

Успешное соединение отдельно от наличия версии: отсутствующий ref, неоднозначное имя branch/tag и непроверенный SHA получают разные сообщения. Пустой репозиторий не выдаётся за источник с существующей веткой. Подкаталог, тип объекта и код этой быстрой проверкой не проверяются — для них выполните Fetch. Изменение URL/пользователя/токена сбрасывает прежний результат; после выбора другой ветки нужно проверить её снова. Проверка необязательна и ничего не сохраняет.

Проверка длится до 20 секунд, не скачивает Git-объекты, не создаёт кандидатов и не меняет работающий сервис. Executor допускает две одновременные проверки, stdout ограничен 512 КиБ/8192 refs, список — 256 ветками с явным предупреждением об усечении. DNS, private-network, TLS и credentials проверяются с теми же ограничениями, что при Fetch; например, подменённый DNS-адрес из служебной сети будет явно отклонён. Для существующего сервиса пустой токен использует сохранённое значение только при прежних URL и имени пользователя.

Нажмите «Получить из Git», просмотрите источник и подтвердите операцию. Admin/Defender может получать код из настроенного источника; настройку меняет только Admin. Операция сохраняется в очереди и продолжает выполняться после закрытия вкладки. При успехе появится кандидат с точным commit SHA. Далее выполните Build, проверьте diff и примените Deploy. Для локального workspace остаётся отдельный Prepare.

Получение не перезаписывает локальный workspace, активный код или игровые данные. Удаление из Git влияет только на зарегистрированные управляемые пути при последующем Deploy. Frozen Compose inputs нельзя менять обычным обновлением; для изменения runtime-политики требуется отдельная поддерживаемая процедура. Ошибка сети, ref или лимита не заменяет предыдущий кандидат. Rollback использует локальные артефакты без Git.

Поддерживаемый профиль:

- HTTPS и проверка TLS; DNS должен возвращать только публично маршрутизируемые адреса. Выбранные адреса закрепляются для Git через [`http.curloptResolve`](https://git-scm.com/docs/git-config/2.40.4#Documentation/git-config.txt-httpcurloptResolve), redirects и ambient proxy отключены.
- GitHub, GitLab и совместимый публичный HTTPS Git-сервер. SSH, GitLab во внутренней сети, provider API, polling и webhooks остаются расширениями.
- Изолированный bare repository и экспорт точных blobs: checkout, hooks, filters, submodules и LFS не исполняются. Git-процессы executor сбрасывают UID/GID до `65534` и очищают дополнительные группы.
- До 120 секунд получения, 64 MiB локальных Git-объектов, 32 MiB экспортированного дерева, 16 MiB одного файла и 20 000 файлов. Предел одного файла учитывает поставляемые CTF-бинарники и исходник SQLite; общий предел дерева остаётся 32 MiB. В Compose действует дополнительный общий `/tmp` tmpfs 128 MiB. Лимиты pack контролируются периодически, поэтому 64 MiB не являются атомарной файловой квотой.
- Symlinks, gitlinks, `.gitmodules`, special files, unsafe paths и LFS pointers отклоняются. `.git` и credentials не включаются в кандидат.

Проверка положительного HTTPS-сценария: `python3 tests/integration/web_registration_git_smoke.py` после сборки runtime-образов. Она использует отдельный временный Compose-стенд и GitHub SibirCTF; её область и ограничения сохранены в отчёте. Unit-тесты `internal/sourcegit` используют закрытый тестовый transport; включить file transport через production API нельзя.
