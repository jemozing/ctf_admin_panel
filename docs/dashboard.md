# Dashboard: запуск, доступ и интерфейс

Dashboard — непривилегированный HTTP-процесс. Он хранит собственную `dashboard.sqlite`, отдаёт встроенную React/TypeScript-сборку и обращается к executor только через типизированный Unix-протокол. Прямого доступа к Docker, файловым деревьям сервисов и базе executor у этого процесса нет.

Основной способ установки описан в [container-deployment.md](container-deployment.md). Образы `dashboard` и `executor` собираются отдельно из общего исходного дерева; постоянные каталоги состояния и UID у них разные.

## Локальная сборка

Для сборки из исходников сначала нужны frontend-артефакты:

```sh
cd web
npm ci
npm run build
cd ..
go build -o bin/ctf-manager ./cmd/ctf-manager
```

`package-lock.json` закрепляет зависимости. `web/dist` встраивается в Go-бинарник, поэтому в рабочем контейнере Node.js и dev-server не нужны. Исходный frontend не требует внешних CDN, шрифтов или сетевого соединения браузера с интернетом.

```sh
bin/ctf-manager init-admin --state /absolute/private/dashboard-state --username admin
bin/ctf-manager dashboard \
  --state /absolute/private/dashboard-state \
  --socket /run/ctf-manager/executor.sock \
  --listen 127.0.0.1:8765 \
  --allowed-hosts localhost:8765,127.0.0.1:8765
```

`init-admin` читает пароль из stdin либо приватного `--password-file`. Пароль не передаётся аргументом команды. Bootstrap разрешён только при отсутствии пользователей; повторный запуск не меняет существующие записи. Каталог состояния должен быть приватным (`0700`), БД — обычным файлом `0600`.

## HTTP и сессии

- Пароли: Argon2id v19, память 64 MiB, 3 прохода, параллелизм 1, индивидуальная случайная соль 16 байт.
- Сессия: случайный токен 32 байта, в БД хранится только SHA-256 токена. Срок — 8 часов; максимум 5 одновременных сессий на пользователя.
- Cookie: `HttpOnly`, `SameSite=Strict`, `Path=/`. При `--secure-cookies=true` используется `Secure` и имя `__Host-ctfsm_session`.
- Изменяющие запросы требуют точного допустимого `Host`, совпадающего `Origin` и `X-CSRF-Token`. Вход требует совпадающего `Origin`, до выдачи сессии CSRF-токен не используется.
- Точные разрешённые `Host` задаются с портом. Заголовки `Forwarded` и `X-Forwarded-*` не меняют доверенную схему, адрес клиента или Host.
- Вход ограничен 5 попытками в минуту на имя пользователя и 30 на IP. Одновременно выполняются максимум 2 проверки пароля. Превышение возвращает `429`.
- Изменение роли, пароля, блокировки или доступа к чувствительным сведениям отзывает все сессии пользователя. Admin также может отозвать их явно.
- **Запуск HTTP-процесса аннулирует все предыдущие сессии.** Это намеренное поведение MVP: восстановленная БД не возвращает действительность старым cookies. Простое открытие БД вспомогательным CLI сессии не отзывает. Восстановление состояния выполняется при остановленном dashboard.
- Последний активный Admin не может быть заблокирован или переведён в другую роль.

При TLS на reverse proxy задайте `--secure-cookies=true` и точный внешний `Host`. HTTP-профиль предназначен для loopback/SSH-туннеля или явно изолированной сети. Для dev-server Vite добавьте его точный Host в allowlist backend; стандартный production-профиль не разрешает порт dev-server.

## Роли

| Действие | Admin | Defender | Viewer |
|---|---|---|---|
| Состояние, релизы, снимки, список операций | Да | Да | Да |
| Preview и запуск разрешённых операций | Да | Да | Нет |
| Логи, имена файлов в diff, подробные события операций | Да | Только при явном разрешении | Только при явном разрешении |
| Пользователи, роли, отзыв сессий, аудит dashboard | Да | Нет | Нет |
| Регистрация и подтверждение проекта внутри разрешённых корней | Да, через панель | Нет | Нет |
| Настройка Git URL/ref/credentials | Да | Нет | Нет |
| Получение кандидата из настроенного Git-источника | Да | Да | Нет |
| Подключение новых host-корней/расширение профиля executor | Локальная настройка установки | Нет | Нет |

Разрешение `sensitive_access` включено для Admin. Для остальных оно выдаётся при создании или изменении пользователя и по умолчанию выключено. Preview без него сохраняет сведения о компонентах и плане, но скрывает список изменённых файлов. Проверки выполняются сервером; скрытие кнопок во frontend не является контролем доступа.

## API

Фиксированные маршруты:

| Метод и путь | Назначение |
|---|---|
| `GET/HEAD /healthz` | Жив ли HTTP-процесс; не состояние Docker или игровых сервисов |
| `POST /api/auth/login` | Вход |
| `GET /api/auth/session` | Текущий пользователь, срок и CSRF-токен |
| `POST /api/auth/logout` | Отзыв текущей сессии |
| `GET /api/status` | Проверка executor |
| `GET /api/services` | Зарегистрированные сервисы |
| `GET /api/registration/options` | Разрешённые корни, только Admin |
| `POST /api/registration/inspect` | Обнаружение существующего проекта по пути, только Admin |
| `POST /api/registration/proposals` | Проверка и создание immutable заявки, только Admin |
| `POST /api/registration/approve` | Подтверждение заявки и постановка инициализации в очередь, только Admin |
| `GET/POST /api/services/{id}/source` | Метаданные / настройка Git-источника; запись только Admin |
| `GET /api/services/{id}` | Контейнеры, отдельные health-сигналы, релизы, снимки, capabilities |
| `GET /api/services/{id}/metrics` | Последние измерения и ограниченная история контейнеров |
| `GET /api/services/{id}/logs?component=...&tail=200` | Ограниченный вывод зарегистрированного компонента |
| `POST /api/preview` | План executor до запуска операции |
| `GET/POST /api/operations` | История / отправка типизированного запроса |
| `GET /api/operations/{id}` | Состояние операции |
| `GET /api/operations/{id}/events` | Подробный журнал при наличии разрешения |
| `GET /api/stream` | WebSocket операций; опционально `service_id` и `component` для логов |
| `GET/POST /api/users` | Список / создание пользователей, только Admin |
| `PATCH /api/users/{id}` | Роль, пароль, блокировка, sensitive_access |
| `POST /api/users/{id}/revoke-sessions` | Отзыв сессий, только Admin |
| `GET /api/audit` | Последние 200 событий dashboard, только Admin |
| `GET /api/packets/status` | Collector/archive status, lease, epoch и счётчики потерь |
| `GET /api/packets` | Metadata-only TCP/UDP список, typed filters и cursor pagination |
| `GET /api/packets/{id}` | Raw record с base64 bytes, только sensitive_access, audit + повторная проверка сессии |
| `POST /api/packets/export` | Бинарный classic PCAP, ≤10 000 пакетов / 8 MiB, sensitive_access, Origin/CSRF и audit |
| `GET /api/capture/policy`, `GET /api/capture/targets` | Желаемая/применённая конфигурация и разрешённые runtime targets, только Admin |
| `POST /api/capture/preview`, `POST /api/capture/confirm` | Immutable preview/digest подтверждение capture scope, только Admin |

Нет универсального proxy-маршрута, передачи команд shell или Docker-аргументов. Путь принимается только отдельными методами регистрации и проверяется executor по bootstrap-корням; обычные операции получают пути из реестра. `initiator` для executor устанавливается backend по серверной сессии. Обычный изменяющий JSON ограничен 16 KiB, описание регистрации — 1 MiB; неизвестные поля отклоняются. Логи показываются как текст, без HTML или ANSI-терминала.

## Интерфейс

Admin добавляет сервис кнопкой «Добавить сервис»: путь → проверка обнаруженных контейнеров/ролей, целей обновления, управляемых путей и классификации хранилищ → просмотр immutable заявки → подтверждение в панели. CLI-подтверждение не требуется. Мастер показывает отдельную операцию инициализации workspace/baseline и не выдаёт принятие регистрации за готовность к Deploy.

На вкладке Git-источника Admin задаёт HTTPS URL, ref, необязательный подкаталог и write-only токен. Пустое поле токена не раскрывает старый секрет; удаление credential задаётся явно. Admin/Defender запускает `fetch_source` через обычный Preview/подтверждение. Готовый кандидат связан с точным commit SHA; следующим шагом является Build. Получение не перезаписывает локальный workspace и не меняет активную игру. SSH, private-network GitLab, polling и API провайдеров пока не входят в этот профиль.

Панель показывает реальные зарегистрированные сервисы, контейнеры и независимые источники проверки. Запущенный контейнер не означает успешную функциональную проверку или положительный ответ checker организаторов. Пока источник не настроен, отображается соответствующее состояние.

На странице сервиса доступны состояние, релизы, снимки, логи, операции и принятая конфигурация. Кнопки включаются только по `capabilities`, полученным от executor, и роли пользователя. Отсутствующие данные не заменяются демонстрационными значениями.

Перед операцией UI запрашивает Preview и показывает компоненты, файлы, образы, ревизию политики, доступность возврата и предупреждение о перерыве. Подтверждение передаёт `plan_digest`; совместимость с постоянными игровыми данными при необходимости подтверждается отдельным флажком. Повтор запроса использует один idempotency key. После изменения плана требуется новый просмотр.

Для `interrupted` / `requires_recovery` доступен просмотр плана восстановления, когда executor разрешает это действие. Возврат проходит тот же цикл Preview → подтверждение. UI не снимает блокировки самостоятельно.

События операций и последние 200 записей логов обновляются через WebSocket раз в 2 секунды. Сессия и актуальные разрешения проверяются перед каждым сообщением, включая повторную проверку после обращения к executor. Соединение не принимает изменяющие команды; payload ограничен 1 MiB, медленный клиент отключается по таймауту записи. HTTP-опрос раз в 5 секунд обеспечивает обновление состояния при обрыве потока. Закрытие вкладки не отменяет операции executor.

Вкладки метрик хоста и контейнеров используют общий кеш executor с периодом 5 секунд и RAM-историей до 60 минут (до 721 точки). UI переключает окно 15/60 минут, показывает gaps/null/reset и устаревшие значения. Источники host-метрик подключаются отдельно при bootstrap; без них значения остаются неизвестными. Первое CPU-измерение требует пары счётчиков; перезапуск контейнера сбрасывает сравнение. Подробные источники, лимиты и проверенные ограничения приведены в [metrics.md](metrics.md).

## Проверки

```sh
npm --prefix web run build
go test -race ./internal/dashboard
```

Тесты проверяют хеширование и хранение сессий, bootstrap, ограничения Host/Origin/CSRF, запрет Viewer до вызова executor, защиту последнего Admin, отзыв сессий после смены роли, ограничение входа и закрытие живого WebSocket после блокировки пользователя. На macOS sandbox для тестовых Unix/HTTP listeners может потребоваться разрешение локальных соединений.

## Пассивные TCP/UDP пакеты

В «Трафик» переключатель HTTP / Пакеты меняет журнал наблюдений. Он не меняет
маршрутизацию или режим WAF. Фильтры пакетов: один/несколько сервисов, компонент,
TCP/UDP, IP/CIDR, оба порта, время и направление; live/pause, страницы и gaps
отображаются отдельно. Для пакета между двумя выбранными концами direction
неоднозначен, есть отдельный фильтр; такой пакет не получает вымышленное
единственное направление относительно выбранного сервиса. Деталь показывает безопасный hex/ASCII Ethernet-кадра,
не исполняет HTML/управляющие байты и не собирает TCP-поток. TLS не расшифровывается.

Opt-in установка, проверенные bridge-цели, короткий runtime lease и ограничения
описаны в [packet-capture-deployment.md](packet-capture-deployment.md).
По умолчанию сохраняются только метаданные. При выключенном capture доступны
настройки и ранее сохранённые записи в пределах retention. Отзыв прав во время
RPC блокирует публикацию raw/PCAP; невыполненный audit также удерживает результат.

## Потоки, gRPC и schemas

«Трафик → TCP-потоки / gRPC» показывает metadata-only conversations и отдельные sensitive детали. TCP представлен двумя направлениями с offset/gaps/retransmit/conflicts; UDP — отдельными датаграммами. HTTP2/gRPC разбирается только из непрерывного префикса; legacy/mixed/unbound версия не получает имён protobuf по текущему релизу. Admin подключает descriptor set через preview/digest/confirm и может удалить его без удаления исходного трафика.

В HTTP detail для `https2` доступен разбор gRPC после TLS termination. Привязанные имена protobuf требуют backend TCP-flow с captured version pins; frontend HTTP exchange не подменяет их текущим состоянием сервиса. [API, лимиты и поддерживаемые профили](traffic-analysis.md#api-и-безопасность).
