# Обязательный функционал MVP

Продолжение разработки 19 октября 2026 года по ТЗ v2.4. Этот перечень отделяет реализацию функций от приёмочных испытаний целевого Linux-хоста. Новые функции удобства не входят в этот пакет.

| Требование | Реализация |
|---|---|
| Проверки сервиса, §13 | TCP connect, одиночный HTTP, ограниченная HTTP-последовательность с cookies и cleanup, прогрев, попытки, общий deadline и TTL. Admin сохраняет полный набор через вкладку «Проверки»; входы хранятся в vault, в ответах API только описание. Ревизия проверок входит в digest плана. |
| Ручная проверка, §13 | Автор, комментарий, время, TTL, точный релиз и runtime digest со StartedAt. Перезапуск и смена экземпляров делают доказательство устаревшим. Ручная проверка не становится автоматическим functional verdict. |
| Отмена, §9.4 | Web и CLI запрашивают отмену. Очередь отменяется до запуска; подготовка останавливается на безопасной границе. После начала мутации процесс не убивается: locks и recovery point сохраняются, требуется Recover. Только подтверждённый возврат допускает итог cancelled. Terminal outcome и освобождение locks записываются атомарно. |
| Снимок → кандидат, §10.2 | Baseline, manual или candidate snapshot становится новым immutable candidate с исходными UID/GID/mode и provenance. Активный сервис и workspace не записываются. Источник закрепляется в графе ротации; чужая или старая file-map отвергается. |
| Файлы и drift, §8–9, §16 | Вкладка «Файлы / Diff»: workspace, candidate, release и active drift, хеши/metadata, ограниченный текст кода. Конфигурационные и чувствительные пути скрыты. Принятие просмотренного file drift требует отдельного нового плана и права просмотра diff; recovery point помечается непроверенной. Runtime/mount drift таким подтверждением не разрешается. |
| Версии и доказательства релизов, §5.3/9.2/16 | Фактические ID/image компонентов, неоднозначность версии и частичное переключение; отдельно наличие image, manifest, frozen configuration и secrets, история операций/проверок и причины недоступности. Возврат к вручную изменённому дереву не объявляет исторический immutable релиз активным или проверенным. |
| Логи, §14.2 | Общий поток сервиса или компонент, stdout/stderr/TTY, время и container ID, pause, tail/time filter, search, RE2 include/exclude, подсветка. Новые container IDs подхватываются при следующем чтении. Ограничения драйвера, усечение и потери показаны явно. |
| Диагностика операций, §14.2/17 | Сохраняется текст Build/Compose, включая ошибки. Известные секреты редактируются до записи; доступ требует sensitive_access. До 20 MiB на операцию и 200 MiB суммарно, ограниченные страницы и счётчики потерь; критические state events не удаляются. См. [logging.md](logging.md). |
| События контейнеров, §14.3 | Независимая подписка Docker events: OOM, restart, die, start, destroy. SQLite, дедупликация и повторное подключение с ограниченным replay; последние 10 000 событий глобально, до 200 в ответе сервиса. Отключение может оставить пробел: ограниченный буфер Docker не даёт гарантии полноты. Метрики за час по-прежнему хранятся в RAM. |
| Планировщик, §12.2 | Отдельные ограниченные lanes сборки, копирования и переключения; приоритет Rollback/Recover. Долгие Build/Git/warmup не удерживают общий gate артефактов; копирование, публикация и критическое переключение сериализованы. Durable locks/pins/reservations защищают квоты и незавершённые артефакты. |
| Эксплуатация, §7/11/15 | Readonly экран квот/ротации; локальные импорт/отзыв/удаление точных версий секретов с зависимостями и подтверждением digest; аудит экспорта backup с UTC/UID. Backup/restore остаются локальными командами. См. [secrets.md](secrets.md), [backup.md](backup.md). |
| Время, §15.5 | Выбор UTC или timezone браузера; исходные timestamps хранятся в UTC. |

Обязательные автоматические проверки входят в обычные `make test`, `make test-race`, `make vet`, `make frontend-check` и сборку TypeScript. Их успешность не заменяет Docker fault injection, испытания медленного клиента или нагрузку на опорном native Linux/amd64-хосте. Результаты и ограничения публикуются в [матрице приёмки](progress.md).
